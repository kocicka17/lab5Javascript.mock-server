# Навчальний REST API (PHP + MySQL)

Універсальний mock-сервер для курсу «Web-розробка мовою JavaScript». Один
набір файлів обслуговує **будь-яку сутність будь-якого варіанта** ER-діаграми —
немає потреби створювати окрему таблицю чи окремий файл під кожен варіант.

## Як це працює

Усі об'єкти зберігаються в одній таблиці `entities`:

| Стовпець      | Призначення                                              |
|---------------|-----------------------------------------------------------|
| `id`          | Автоінкрементний ідентифікатор                            |
| `entity_type` | Довільна назва сутності, яку обирає студент (напр. `book_ivanenko`) |
| `data`        | Усі атрибути обʼєкта у форматі JSON (`{"title": "...", "author": "..."}`) |

Завдяки цьому та самому файлу `api.php` можуть одночасно користуватись усі
студенти з усіма 30 варіантами — кожен просто обирає свою унікальну назву
`type` (рекомендація: додавати прізвище, напр. `issuance_petrenko`).

## Файли

- `schema.sql` — SQL-скрипт створення бази даних і таблиці
- `config.php` — налаштування з'єднання з MySQL (**відредагуйте перед розгортанням**)
- `api.php` — сам REST API (єдина точка входу)

## Розгортання

1. Створіть базу даних і таблицю, імпортувавши `schema.sql`:
   ```
   mysql -u root -p < schema.sql
   ```
   (або виконайте вміст файлу через phpMyAdmin / інший клієнт).

2. Створіть окремого користувача MySQL для API (не використовуйте root):
   ```sql
   CREATE USER 'js_api_user'@'localhost' IDENTIFIED BY 'ВАШ_ПАРОЛЬ';
   GRANT SELECT, INSERT, UPDATE, DELETE ON js_course_api.entities TO 'js_api_user'@'localhost';
   FLUSH PRIVILEGES;
   ```

3. Відкрийте `config.php` і вкажіть реальні значення `$DB_HOST`, `$DB_NAME`,
   `$DB_USER`, `$DB_PASS`.

4. Завантажте `config.php` та `api.php` на PHP-хостинг (потрібен PHP 8.0+ з
   розширенням `pdo_mysql`, увімкненим за замовчуванням у більшості хостингів).

5. Перевірте роботу, відкривши в браузері (має повернутись `[]`):
   ```
   https://ваш-домен/api.php?type=test
   ```

6. Повідомте студентам базову адресу (наприклад,
   `https://ваш-домен/api.php`) — це і є `API_BASE_URL`, який вони
   підставляють у свій JavaScript-код.

## Перевірка вручну (curl)

```bash
# Створити обʼєкт
curl -X POST "https://ваш-домен/api.php?type=book_test" \
  -H "Content-Type: application/json" \
  -d '{"title":"Кобзар","author":"Тарас Шевченко"}'

# Отримати список
curl "https://ваш-домен/api.php?type=book_test"

# Оновити (id підставте зі списку)
curl -X PATCH "https://ваш-домен/api.php?type=book_test&id=1" \
  -H "Content-Type: application/json" \
  -d '{"publisher":"Дніпро"}'

# Видалити
curl -X DELETE "https://ваш-домен/api.php?type=book_test&id=1"
```

## Примітки з безпеки (навчальний контекст)

- CORS дозволено з будь-якого джерела (`Access-Control-Allow-Origin: *`) —
  прийнятно для навчального стенду, але НЕ використовуйте таке налаштування
  для реального продакшн-проєкту.
- Параметр `type` перевіряється регулярним виразом (лише латиниця, цифри,
  підкреслення) — захищає від SQL-ін'єкцій через цей параметр.
- Усі запити до бази даних виконуються через підготовлені вирази (PDO
  prepared statements).
- Дані всіх студентів зберігаються в одній таблиці без розмежування прав
  доступу — це навчальний стенд, а не production-система; будь-хто, хто
  знає чи вгадає `type` іншого студента, може прочитати або змінити його
  дані. Якщо це критично, можна додати просту токен-авторизацію, але для
  цілей курсу такий рівень захисту зазвичай надлишковий.
- Рекомендований обсяг: сервер розрахований на навчальне навантаження
  (одна академічна група), а не на промислові обсяги трафіку.

## Тестування логіки без MySQL

Файл `api.php` було перевірено локально через `config.php`, що
підключається до SQLite замість MySQL (лише для розробки/тестування —
у робочому розгортанні використовуйте наведений `config.php` з MySQL).
Усі CRUD-операції, обробка помилок (400/404/405), CORS-заголовки та
OPTIONS-preflight підтверджено працюючими коректно.
